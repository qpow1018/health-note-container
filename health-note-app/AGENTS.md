# Health Note App

Expo·React Native·TypeScript로 Health Note 웹의 WebView와 네이티브 연동을 제공한다. npm과 package-lock.json을 사용한다. [공통 작업 지침](../AGENTS.md)을 함께 따른다.

- React Native·Expo 코드, WebView 연결, 네이티브 모듈, 권한·백그라운드 동작 작성·수정·리뷰에는 [following-health-note-app-boundaries](.agents/skills/following-health-note-app-boundaries/SKILL.md)를 적용한다.

## 역할과 경계

- 앱은 WebView 표시, 로딩·연결 오류 안내, 시스템 인증 브라우저와 앱 복귀, 외부 URL 처리, Android 뒤로가기와 안전 영역을 담당한다.
- 제품 화면·하단 메뉴·운동·루틴·완료 기록은 웹이 담당한다. 요청에 필요하지 않은 네이티브 화면·라우터·데이터 상태를 중복 추가하지 않는다.
- 현재 구현은 판단의 출발점이며 영구적인 제약은 아니다. 책임 경계를 바꿀 필요가 있으면 이유와 웹·앱에 미치는 영향을 설명한다.

## 연결 변경 시 확인

- 인증 URL·callback·앱 scheme·웹과 주고받는 메시지·라우팅을 변경하면 관련 웹 구현과 호출부를 함께 확인한다. 서버나 플랫폼의 허용 URL 설정에 영향이 있으면 필요한 변경을 명시한다.
- 인증 연결을 바꿀 때는 코드 교환 주체와 저장소 경계를 확인한다. 시스템 브라우저와 WebView의 세션이 자동 공유된다고 가정하지 않는다.
- URL 허용 범위나 메시지 검증을 변경하면 정상 흐름과 거절해야 할 입력을 함께 확인한다. 오류를 피하기 위해 허용 범위를 일괄 확대하지 않는다.

## 검증

- 코드 변경은 lint·typecheck와 변경에 관련된 최소한의 테스트로 검증한다. 기존 테스트를 우선 활용하고 매번 전체 테스트나 새 테스트 파일을 강제하지 않는다.
- 환경·의존성·빌드 설정 변경은 번들 빌드도 확인한다. 네이티브 설정·권한·모듈 변경처럼 번들 생성만으로 확인할 수 없는 변경은 영향받는 플랫폼의 네이티브 빌드를 수행한다.
- 인증 브라우저 복귀·WebView 탐색·하드웨어 뒤로가기·안전 영역·키보드·터치처럼 기기 차이가 중요한 변경은 관련 흐름을 실제 기기에서 확인한다. 환경상 실행하지 못하면 항목과 이유를 명시한다.
- 모의 이벤트·API 기반 테스트, JS·Hermes 번들 생성, APK·IPA 네이티브 빌드, 설치와 실기기 동작 확인을 구분한다. 앞 단계의 성공으로 다음 단계까지 검증했다고 보고하지 않는다.
- 문서만 변경한 작업은 링크·설정·포맷 등 관련 검사로 제한한다.

## 문서

- 실행·환경·빌드·검증 명령은 [README](README.md), 현재 WebView·인증·탐색 구조는 [앱 아키텍처](docs/architecture.md)를 확인한다. 문서 설명은 관련 코드와 대조한다.
- 책임 경계나 연결 동작을 변경하면 관련 문서도 갱신한다. 코드의 세부 내용을 반복하거나 날짜별 작업 보고를 README에 누적하지 않는다.
