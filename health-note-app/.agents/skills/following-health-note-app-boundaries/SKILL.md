# Health Note 앱 작성과 책임 경계

[앱 지침](../../../AGENTS.md)과 [공통 지침](../../../../AGENTS.md)을 함께 따른다. 현재 구조는 [앱 아키텍처](../../../docs/architecture.md)를 출발점으로 관련 코드와 대조한다. 실행·빌드·검증 명령은 [README](../../../README.md)를 확인한다.

## 작성 전 책임 판단

- 제품 화면·도메인 데이터와 네이티브 기능의 책임을 구분한다. 웹 화면·라우터·계정 상태를 앱에 중복 구현하지 않는다. 책임을 옮길 필요가 있으면 이유와 웹·앱에 미치는 영향을 설명한다.
- React 화면과 연결 제어, 네이티브 모듈 호출, 플랫폼의 센서·서비스·저장 책임 중 어디에 해당하는지 판단하고 작성 위치를 정한다.
- 현재 App.tsx나 기존 모듈을 모든 기능의 추가 위치로 고정하지 않는다. 파일 길이보다 책임과 읽는 흐름을 기준으로 분리하고, 단일 사용처를 위한 공통 브리지나 서비스 계층을 미리 만들지 않는다.

## TypeScript·React Native

- 기본 타입 선언은 type, 타입 이름은 T 접두사, 타입 import는 import type을 사용한다. 컴포넌트와 이름 있는 헬퍼는 함수 선언식으로 작성한다.
- 컴포넌트 파일은 import → 모듈 수준 타입·상수 → 대표 컴포넌트 → 보조 함수·지역 컴포넌트 순으로 둔다. 순서를 맞추려고 책임이나 스코프를 바꾸지 않는다.
- 인라인 콜백과 effect 정리 콜백은 화살표 함수를 기본으로 한다. 여러 책임이 섞인 처리는 이름 있는 함수로 분리하되 단순한 계산까지 기계적으로 분리하지 않는다.
- 화면에 표시할 값은 state, 렌더링과 무관한 이벤트 처리용 값은 ref 등 용도에 맞게 관리한다. 같은 정보를 state·ref·네이티브 저장소에 복제하기 전에 각각 필요한 이유를 확인한다.
- React Native의 기존 StyleSheet와 컴포넌트 방식을 따른다. 웹의 DOM·SCSS·브라우저 API를 그대로 옮기지 않는다. Kotlin에는 TypeScript의 문법·명명 규칙을 강제하지 않고 해당 모듈의 스타일을 따른다.

## 이벤트와 플랫폼 수명

- 이벤트 구독은 소유 위치와 해제 시점을 함께 정한다. 앱 복귀·문서 로드 등 여러 진입점이 같은 비동기 작업을 호출하면 중복 실행과 오래된 결과의 영향을 확인한다.
- AppState 리스너·타이머·재시도는 현재 필요한 동작에만 추가한다. 앱 실행당 한 번, 화면 진입마다, 앱 복귀마다 수행할 작업을 구분한다.
- 권한 거절, 시스템 요청 차단, 설정에서 권한 변경, 앱 복귀를 구분한다. 재요청 시점과 안내는 기능 요구사항에 맞추고 반복 이벤트마다 권한을 요청하지 않는다.
- Android·iOS·Expo Go·네이티브 모듈 미지원 환경에서 가능한 동작을 구분한다. 미지원·권한 부족·실행 실패를 성공이나 빈 데이터로 숨기지 않는다.
- 백그라운드 처리는 JS나 WebView가 계속 실행된다고 가정하지 않는다. 프로세스 종료·재부팅·강제 종료 시 재개와 데이터 보존 범위를 요구사항 및 실제 플랫폼 동작과 대조한다.
- 생성되는 android/·ios/ 파일을 수정하기 전에 Expo 설정·config plugin·로컬 모듈 등 재생성 후에도 변경을 유지할 위치를 확인한다. 불필요한 네이티브 의존성을 추가하지 않는다.

## 웹과 네이티브 연결

- URL·앱 scheme·callback·메시지를 바꾸면 웹의 발신·수신 코드와 앱의 처리 코드를 함께 확인한다. 허용 출처와 메시지 종류·입력·응답·실패 동작을 명확히 한다.
- WebView 메시지는 발신 URL의 origin과 payload를 확인한 뒤 처리한다. 주입 스크립트는 대상 origin을 확인하고 값을 안전하게 직렬화한다. 오류 해결을 위해 URL이나 메시지 허용 범위를 일괄 확대하지 않는다.
- 웹·시스템 인증 브라우저·네이티브 저장소의 세션이 자동 공유된다고 가정하지 않는다. 인증 변경은 코드 교환 주체와 저장소 경계를 확인한다.
- 화면 이동·뒤로가기·안전 영역·키보드 처리는 웹과 앱이 같은 동작이나 공간을 중복 처리하지 않도록 소유 주체를 확인한다. 현재 기기의 우연한 결과를 모든 OS의 동작으로 일반화하지 않는다.

## 완료 전 검토와 검증

- 제품 코드 변경은 완료 보고 전에 [self-review-health-note-changes](../../../../.agents/skills/self-review-health-note-changes/SKILL.md)를 적용한다. 검증 중 코드를 수정하면 영향을 받는 부분을 다시 검토·검증한다.
- [test-feature-behavior](../../../../.agents/skills/test-feature-behavior/SKILL.md)와 앱 지침에 따라 변경을 확인할 최소한의 의미 있는 검증을 선택한다. 별도 읽기 전용 리뷰에서는 테스트나 제품 코드 수정을 자동 실행하지 않는다.
- 모의 이벤트 테스트, JS 번들, 네이티브 빌드, 설치·실기기 동작 확인을 구분한다. 기기가 없어 확인하지 못한 권한·앱 복귀·백그라운드·터치 동작은 미확인으로 보고한다.
