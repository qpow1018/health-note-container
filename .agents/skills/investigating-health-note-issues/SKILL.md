# 실사용 이슈 조사와 기록

웹·앱의 관찰된 문제를 재현 조건, 기존 구현, 확인 근거와 연결해 기록한다. 버그·성능·사용성 문제 중 무엇인지 조사 전에 확정할 필요는 없다. 기록은 해결 과정의 근거이며 포트폴리오용 성공 서사를 미리 작성하는 문서가 아니다.

## 요청 범위

- '조사하자'와 '처리하자'는 동일하게 이슈 기록·조사·해결안·영향·검증 방법 제시까지 수행한다. 표현이 포괄적이거나 원인이 명확해 보여도 제품 코드 수정 권한으로 해석하지 않는다.
- 조사에는 관련 코드·테스트·Git 이력 확인과 필요한 최소한의 재현·측정을 포함한다. 전체 테스트나 새 테스트 파일을 일괄 추가하지 않는다. 실제 사용자 데이터·운영 설정을 변경하는 재현은 포함하지 않는다. 민감한 로그·계정 식별 정보·토큰은 문서에 남기지 않는다.
- 해결 방향에 대한 동의만으로 수정을 시작하지 않는다. '이 방법으로 수정하자'처럼 수정 실행을 요청받으면 기존 구현·테스트 지침에 따라 수정·검증하고 같은 이슈를 갱신한다. 이미 주어진 명시적 수정 권한은 반복해서 확인하지 않는다.
- 새 기능이나 정책 선택이 필요하면 관련 선택만 기획 대화로 이어간다. 문제 제보 전체를 새 기능 기획으로 돌리거나 추측한 해결책을 먼저 구현하지 않는다.

## 등록과 조사

- 작업 공간 루트의 `docs/issues/README.md`와 관련 이슈를 먼저 찾아 중복이면 기존 문서를 이어 쓴다. 여러 증상을 하나의 원인으로 미리 묶지 않는다.
- 새 이슈는 기존 최대 번호 다음의 `NNN-short-slug.md`로 작성한다. 목록에도 등록한다. 재현하지 못했어도 사용자 제보로 등록할 수 있고, 사용자 관찰과 직접 확인한 사실을 구분한다.
- 환경·동작 순서·기대와 실제 결과·발생 빈도를 확인한다. 코드로 알 수 없는 기기나 체감 상황 등 조사에 필요한 정보만 질문하고, 답변 없이 가능한 코드 조사는 계속한다.
- 조사 시작 시 Git HEAD와 관련 경로를 기록한다. 미커밋 변경이 있으면 HEAD만으로 당시 코드를 대표하지 못함을 명시하고 관련 차이를 기록한다. 현재 파일 링크와 과거 커밋 기준 경로를 구분한다.
- 관련 진입점·호출부·저장/API·웹과 앱 연결을 좁혀 읽는다. 기존 코드의 실제 동작과 작성 의도를 구분하며, 작성 이유에 근거가 없으면 추정이라고 밝힌다.
- 가설마다 확인 방법과 결과를 연결한다. 코드상 가능한 원인, 재현된 원인, 아직 확인하지 못한 부분을 구분한다. 느리다는 제보에 측정 없이 시간·개선율을 붙이지 않는다.
- 해결안은 확인된 근거에 맞춰 추천안과 실제 대안·절충, 영향 범위, 검증 방법을 제시한다. 조사 결과를 공유하고 수정 실행 요청을 기다린다. 환경이 막히면 원인을 단정하지 않고 필요한 다음 확인을 남긴다.

## 이슈 문서

문서에는 다음 내용을 작업 규모에 맞게 남긴다. 미확인 항목을 채우기 위해 사실을 만들지 않고 '미확인' 또는 '미실행'으로 표시한다.

- 등록일·관련 웹/앱·조사 기준 커밋과 미커밋 변경 여부
- 현상·환경·재현 순서, 기대 동작과 실제 결과
- 기존 구현과 관련 코드·테스트 근거
- 가설·확인 방법·결과, 확인된 원인과 남은 불확실성
- 제안한 해결안·이유·영향·검증 계획, 사용자 결정
- 수정이 진행된 경우 실제 변경·수정 커밋·검증 결과와 한계

별도 상태 필드는 관리하지 않는다. 목록은 이슈를 찾는 용도로 사용하고, 본문에 조사 결과·실제 수정·커밋·검증 결과와 미확인 사항을 기록한다. 중단하기로 결정했다면 이유를 본문에 남긴다.

- 수정한 사실과 검증한 범위를 구분하고, 남은 확인 사항을 본문에 명시한다. 모의 API·브라우저 결과를 실제 기기·운영 검증으로 확대하지 않는다.
- 수정 후에는 제안과 실제 처리의 차이를 갱신하고 실패한 가설도 판단에 유용한 근거만 남긴다. 커밋 전에는 커밋을 예정·미작성으로 표시하고 해시를 만들지 않는다. 커밋 시에는 포함 범위를 설명하고 실제 해시를 후속 기록한다.
- 제품의 현재 구조·정책이 바뀌면 해당 아키텍처·동작 문서도 갱신한다. 이슈 기록으로 현재 문서를 대체하거나 README에 조사 보고를 누적하지 않는다.
- 별도 장문 보고서를 반복하지 않는다. 대화에는 이슈 링크, 핵심 근거·불확실성, 추천 해결안과 다음 결정을 간결하게 제공한다.
