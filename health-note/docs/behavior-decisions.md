# 제품 동작 정책

사용자의 기록·일정에 영향을 주는 서비스 동작을 정리한다. 구현 방식, 캐시 설정, 리팩터링 이력은 다루지 않는다. 아래는 현재 코드와 테스트에서 확인한 정책이며, 선택 이유가 확인되지 않은 내용에 이유를 덧붙이지 않았다. 요구사항이 바뀌면 관련 코드·테스트와 함께 갱신한다.

## 닉네임은 마이페이지에서 설정한다

닉네임을 저장하지 않은 계정은 기본 이름 `회원`을 표시한다. 첫 로그인에는 입력 단계를 추가하지 않는다. 마이페이지의 닉네임 변경 메뉴에서 팝업을 열어 한글 완성형·영문·숫자 1~10자로 변경할 수 있으며 공백·특수문자·빈 값은 허용하지 않는다. 중복과 변경 횟수 제한은 없다. 저장 실패 시 입력을 유지하고 재시도할 수 있다. 취소·Escape는 미저장 입력을 버리며 저장 중에는 팝업을 닫지 않는다. 저장한 닉네임은 홈에 표시한다.

닉네임은 Supabase Auth 사용자 메타데이터의 `nickname`에 저장하며 계정 구분·권한 판단에는 사용하지 않는다. 기존 계정은 최초 표시를 위해 별도 저장 요청을 보내지 않는다.

근거: [닉네임 폼](../src/features/profile/NicknameForm.tsx), [저장 API](../src/api/auth/index.ts). 관련 테스트: [마이페이지](../tests/my.spec.ts).

## 운동 연결 해제와 데이터 삭제는 다르게 처리한다

- 루틴에서 운동을 제외해도 해당 운동의 기존 완료 기록은 남는다. 현재 루틴의 진행률 계산에서는 제외한다.
- 루틴 자체를 삭제하면 그 루틴의 완료 기록도 삭제한다.
- 운동 자체를 삭제하면 그 운동의 완료 기록도 삭제한다. 다만 루틴에 포함된 운동은 먼저 모든 루틴에서 연결을 제거해야 삭제할 수 있다.

근거: [완료 기록 DB 계약](../supabase/migrations/20261016111342_create_routine_progress.sql), [루틴 연결 DB 계약](../supabase/migrations/20261016090226_create_routines.sql), [홈 진행률 계산](../src/features/routine/homeRoutines/HomeRoutines.tsx). 관련 테스트: [완료 기록 보존·삭제](../supabase/tests/progress.test.sql).

## 루틴 활성화는 일정이나 기록을 초기화하지 않는다

새 루틴은 비활성 상태로 시작한다. 홈의 오늘 운동 대상은 활성화된 루틴 중 오늘 일정에 해당하는 루틴이다. 관리 목록에서는 비활성 루틴도 확인할 수 있다.

활성화·비활성화는 루틴의 운동 구성·일정·미루기 내역과 기존 완료 기록을 초기화하지 않는다. 다시 활성화할 때 활성화 날짜를 새로운 시작일로 삼지 않고 기존 일정으로 예정일을 계산한다.

근거: [루틴 DB 계약](../supabase/migrations/20261016090226_create_routines.sql), [활성 상태 변경](../src/api/routine/index.ts), [홈 대상 선택](../src/features/routine/homeRoutines/HomeRoutines.tsx), [일정 계산](../src/features/routine/routineSchedule.ts). 관련 테스트: [활성 상태](../tests/routine-active.spec.ts), [다음 예정일](../tests/routine-next-date.spec.ts).

## 반복 일정 변경 시 미루기 내역을 구분한다

간격 반복 루틴의 이름·메모·운동 구성만 수정하고 시작일과 반복 간격을 유지하면 기존 미루기 내역도 유지한다. 시작일이나 반복 간격을 바꾸면 미루기 내역을 초기화한다. 요일 반복으로 바꿀 때도 기존 간격 반복의 미루기 내역을 이어받지 않는다.

근거: [루틴 수정 값 준비](../src/features/routine/routineActions.ts), [폼 안내](../src/features/routine/routineForm/RoutineForm.tsx). 관련 테스트: [일정 수정과 미루기 내역](../tests/routine-postpone.spec.ts).

## 루틴 저장은 입력 검증 후 운동 존재 여부를 확인한다

루틴 폼은 이름·운동 선택·반복 일정의 입력 오류를 먼저 안내한다. 유효한 입력에 대해서만 운동 목록을 재조회해 선택한 운동이 여전히 존재하는지 확인하고 저장한다. 조회 실패는 운동 목록 오류 영역에서 한 번만 안내하며 입력을 유지한다. 운동 선택을 다시 열어 조회에 성공하면 저장을 재시도할 수 있다.

근거: [루틴 폼](../src/features/routine/routineForm/RoutineForm.tsx). 관련 테스트: [입력 검증 순서와 조회 실패 복구](../tests/routine-refetch.spec.ts).


## 걸음은 Android 휴대폰에서 자동 기록한다

첫 범위는 오늘 걸음수와 화면 꺼짐·백그라운드 자동 기록이다. 앱을 새로 실행할 때 권한이 없으면 한 번 요청하고, 권한이 있으면 기본으로 측정한다. 홈에는 켜기·끄기 버튼을 두지 않는다. 권한을 거절해도 나머지 기능은 사용할 수 있으며 같은 실행 중 잠금 해제·앱 복귀에서는 다시 묻지 않는다. 시스템이 재요청을 차단한 경우에는 설정 열기 안내를 제공한다. 걷기·달리기 구분, 활동 시간·칼로리, 수동 운동 시작·종료는 포함하지 않는다.

첫 버전의 걸음 기록은 로그인 계정이 아닌 휴대폰 내부에 저장한다. 계정 변경으로 값을 초기화하지 않으며 서버에 동기화하지 않는다. 앱 제거·데이터 삭제 시 사라진다. 측정 전이나 중단 구간의 걸음수를 추정해 추가하지 않는다. 자정을 걸친 센서 묶음의 날짜 배분과 강제 종료·OS 제한은 [앱 문서](../../health-note-app/docs/architecture.md#android-자동-걸음-기록)의 제약을 따른다.

근거: [홈 걸음 카드](../src/features/steps/StepCard.tsx), [네이티브 측정](../../health-note-app/modules/health-note-steps/android/src/main/java/expo/modules/healthnotesteps/StepTrackingService.kt). 관련 테스트: [브리지 응답을 대체한 화면 동작](../tests/steps.spec.ts), [센서 누적값 계산](../../health-note-app/modules/health-note-steps/android/src/test/java/expo/modules/healthnotesteps/StepCounterTest.kt).


테스트용 임시 기능으로 홈 카드에 오늘 기록 초기화를 제공한다. 확인창에서 초기화하면 오늘 저장값만 0으로 만들고 센서 기준을 다시 잡는다. 자동 기록은 계속되고 이전 날짜 기록도 유지한다. 초기화 시점 이전의 지연 센서 이벤트는 무시하고, 이후 첫 응답은 기준값으로만 사용하므로 첫 응답까지의 일부 걸음은 집계되지 않을 수 있다. 검증 후 제거할 기능이며 웹 메시지의 `reset` 요청을 앱이 처리한다.


## 시간대별 활동과 자동 활동 구간

짧은 움직임도 시간별 합계에 남긴다. 짧은 멈춤을 포함한 활동 시간 합계 3분 이상인 경우 별도 활동으로 묶고, 3분간 움직임이 없으면 마지막 움직임 시각으로 종료한다. 3분 이내 재개는 같은 구간으로 연결한다. 30초 미만의 멈춤은 활동 시간에 포함하고, 30초 이상 대기는 마지막 걸음 이후 구간 전체를 제외한다. GPS는 짧은 멈춤과 대기 중에도 활동 종료까지 유지하지만 대기 중 위치 흔들림은 거리에 더하지 않는다. 걷기·달리기 종류가 섞이면 한 구간으로 유지하고 섞인 종류로 표시한다. 두 3분 기준은 시험 기준이다.

거리는 위치 확보 구간만 합산하고 위치가 없는 구간은 보폭 추정으로 채우지 않는다. 평균 속도의 분모도 같은 유효 위치 구간의 이동 시간이다. 거리·속도 권한을 거절해도 걸음·활동 시간 기록은 유지한다. 자동 수집 시작 알림은 안내이며 확인 버튼을 누르지 않아도 기록한다.

오늘 초기화는 오늘 총걸음수·시간별 집계·활동 목록 전체를 지우며 이전 날짜와 자동 측정은 유지한다. 과거 총걸음수에서 과거 활동 시간·위치 기록을 복원하지 않는다. 시간별 기록의 시작 시각을 상세에 표시한다. 원시 위치는 저장하지 않고 기기 내부에 거리·시간 합계만 저장한다.

## 로그아웃 확인

마이페이지에서 로그아웃을 누르면 확인창을 연다. 취소·Escape는 로그인 상태를 유지하며, 확인창의 로그아웃을 눌러야 요청한다. 요청 중에는 확인창을 닫고 로그아웃 버튼을 비활성화한다.
